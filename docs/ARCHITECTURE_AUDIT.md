## 验证证据

- 累计差异可用 `git diff --check 1c99399..main` 核对。Python 规则和源码契约通过 516 项，另有 16 项跳过。源码契约只核对接入点和形态。
- 构建授权后，导航与感知优先核对 `performancePoliciesTest`、`behaviorScopedWorkBudgetTest` 和 `perceptionPolicyTest`。动作、配置、存档使用 `behaviorActionCoordinatorTest`、`behaviorGrowthConfigTest`、`vnextEconomyRecoveryTest`、`vnextFactionContentNbtTest`。这些入口已在 build.gradle 登记，尚未执行本轮累计改动的 Java 验证。
- 游戏内验证分别覆盖群战性能、联动缺席/存在、存档恢复和两人同时操作。每个场景需要独立证据，不能由编译或 Python 检查代替。

## 已核查的外部做法

- [Linux 实时调度队列](https://github.com/torvalds/linux/blob/master/kernel/sched/rt.c)采用每优先级一条队列。听觉只有五个固定等级，直接按等级分队即可，入队无需搬移积压，取最高等级最多检查五条队列。512 条总容量、同等级先入先出、满时淘汰最低等级尾部及处理进度均保留。
- [Unreal Animation Budget Allocator](https://dev.epicgames.com/documentation/unreal-engine/animation-budget-allocator-in-unreal-engine)用画面重要程度动态调整动画更新。与现有距离/人数分档同方向，是否引入帧耗时反馈需先检查当前分档的成本和兼容动画状态。
- [Valve Source NPC 小队策略槽](https://github.com/ValveSoftware/source-sdk-2013/blob/master/src/game/server/ai_basenpc.cpp)通过释放可占用槽位协调共享目标。HHU 已有拾取目标占位，战斗中能否借鉴需先区分开火资格、选敌及移动位置争用。

- [Linux 调度带宽回收](https://docs.kernel.org/6.13/scheduler/sched-deadline.html)区分实际执行和可回收的预算。HHU 在 FairWorkBudget 内退回明确取消或实际未使用的预约余额。既有阵营轮转、每 tick 上限和已执行计数保留。未调用取消的离场请求仍依赖既有过期机制。

- 感知队列核对了维度与全服原子预约，以及饱和维度不会阻塞其他维度。沿用导航轮的预算回收原则，取消、缩小和无效预约均按原维度归还未使用余额，同时归还全服额度。需求所属阵营与批次规则沿用现有调度。

## 战斗动作权限

- HumanBehaviorControl 在多个同 tick 入口推进时钟。ActionCoordinator 每个时钟值只执行一次到期扫描，直接通过迭代器移除到期动作。正常取得空闲资源时无需创建抢占清单。
- 抢占仍先验证整组资源，失败时保留所有旧所有者。会话关闭先禁止准入，再执行实际移动、枪械、恢复等清理，最终取消旧令牌。权限回收与物理动作收尾是两层职责。

- 恢复按真实消耗回执结算，并在原版停止用物回调前撤销会话。枪械会话取消沿真实手部与背包堆栈逐项委派给联动适配器。修复其中一把武器的适配器抛出运行时异常时，其余枪械无法获得取消通知的问题；本地托管与战术状态在 finally 中收尾。联动异常下该适配器自身内部状态仍需由其实现处理。
- 枪械清理采用与 [Java 资源清理规范](https://docs.oracle.com/javase/specs/jls/se17/html/jls-14.html#jls-14.20.3) 相同的异常保留原则。各武器独立尝试，首个运行时异常在本地清理后上报，其余附在首个异常下。

## 监控退出

- 已追踪主动退出、切换、目标离场、断线及停服到服务端会话关闭。关闭时先撤销会话，再逐项释放远程视点、接管、背包和客户端显示。某个运行时异常不应跳过其他步骤。接管战斗清理异常时仍清空移动输入。渲染、UI 和远程音频的源码结果见对应章节。

## 建筑模板

- 导出先在同目录写完整临时 NBT。覆盖要求原子移动，失败返回错误，新建不覆盖已有文件。缓存仅在提交后失效。
- 放置前保护既有建筑信息方块，原实现最多逐格检查 262144 次。现复用原版已加载区块的方块实体位置索引，包含待加载数据，只对实际落在模板范围内的候选核查类型。预览几何、注册和存档格式沿用现有接口。

## 经济库存事务

- 钱包及实物提交先在副本上计算，再校验真实槽位。账本保存 PREPARED 并调用库存提交，之后推进政治状态和回执。发现 Curios 等槽位写入抛错时旧回滚会改写尚未触及的槽位，且单槽回滚异常会中止其他恢复。现按实际尝试过的写入逆序恢复，校验恢复值并保留失败项供账本重试。重启恢复和培养结算见对应章节，异常落盘仍需实测。

- 经济重启恢复增加前序凭证检查。库存摘要可以在不同交易后碰巧相同，只能证明当前库存内容。比较 [SQLite 原子提交](https://www.sqlite.org/atomiccommit.html) 的跨文件协调机制后，保留 Minecraft 存档格式和保守恢复路径。Minecraft 的多个存档文件依然独立落盘。

## 客户端人类渲染

- 视图分档使用上一帧绘制数量及相机距离，摄像机目标、手臂和容器预览保留完整呈现。共享模型每次恢复初始姿势与动画绑定，避免上一实体姿势泄漏。
- 同一绘制入口复用一次举盾手判断，常规手持物不再进入可选枪械识别，只在原生充能弩姿态可能与枪械姿态冲突时核查。沿用现有远近分档和联动动画优先级。后续须用游戏内帧时间判断引入动态预算的收益。

## 网络输入检查

- 按 [Forge SimpleImpl](https://docs.minecraftforge.net/en/1.20.x/networking/simpleimpl/#handling-packets) 核对服务端主线程、消息方向和客户端坐标的已加载区块检查。已确认作者编辑器、模板放置和选区绑定使用服务端权限。补齐框选棒直接点击的区块检查。
- 属性详情的客户端打开请求改为在实体查找前限流，实体 ID 与 UUID 匹配后再走共用权限和快照入口。监控控制包已有有限浮点、世代和序号校验，其他联动和注入仍待核查。

## 可选联动注入

- 对照 [Mixin Redirect 规范](https://javadoc.io/static/net.fabricmc/sponge-mixin/0.15.0%2Bmixin.0.8.7/org/spongepowered/asm/mixin/injection/Redirect.html#allow())。焦燃盾牌拦截允许恰好一处注入，但原门控只确认至少一处。现在门控与注入共享完整方法描述符，只有调用点恰好一处才启用，否则保留焦燃原生拦截。其他可选注入的变体覆盖仍待核对。

## 配置迁移

- 分阶配置布局刷新与成长迁移从同一字节快照解析、备份和校验，避免两次读文件得到不同版本。[Git 条件更新](https://git-scm.com/docs/git-update-ref)展示了同类前置校验和写锁的组合。这里保留现有外部编辑器兼容性，文件最后一次比较到移动之间仍有竞争窗口，跨多个配置文件也不保证原子性。

## 雇佣召回

- 已核对名册所有权、按 UUID 查已加载实体、来源区块票据及跨维度迁移。召回走实体原生迁移，不从名册重新构造实体。玩家断线现在立即撤销其排队及活动召回，归还已占用的区块票据；其余玩家保留原队列。异常迁移和救援分支仍待验证。

## 培养结算

- 已核对候选签名、同一士兵不能重复开始付费周期、座位/权限校验和离线补发。完成周期先在内存计算材料扣除及完成状态，再应用到实体。预约余额校验失败时，实体不会先获得属性。离线结果应用成功后显式标记账本待保存。跨文件落盘仍需实测恢复。

## 长距离寻路

- 每个用途保存独立目标和失败记录，远程额度则按实体共享。原用途取消会无条件撤销该实体的远程申请。现在由实际申请的用途持有等待权，单用途取消只释放自己的申请，实体级取消仍覆盖全部用途。

- 闲置拾取的掉落物占位推迟到实际启动追踪。候选搜索只筛选，任务未启动不占位。确认位置失效或换目标失败时清掉追踪标记，仍沿用占位到期和停止释放规则。

## 全局预算面板

- F8 服务端快照只读已有计数和档位。客户端同页刷新改为更新现有文本行，行数变化才重建控件；不可见页的数据变化不会重排本页。变化行仍走共用布局以正确处理换行。

## 自然战场生成

- 战场成员选位先检查候选区块已加载，再读取地表和碰撞。原实现遇到第一个通过原版检查但未通过模组安全规则的位置就退出，现在继续使用剩余尝试次数。未加载区块不会被当成可用空地。

- 阵营刷怪笼写入保留延迟、范围和出生条件，仅替换身份候选。实体读取先复制模板，加入世界时才消费出生标记，磁盘载入不会重新配装。作者装备识别改为检查原版列表类型，错误类型不会阻止自动装备。

## 友军报告传播

- 报告先检查接收方是否已知目标，再检查同阵营、权限和联络射线。整次投递复用一次同维度目标查找。没有新接收方时不再构造待发报告和重复计算该报告威胁。保留原有链式去重、分档频率及可转发证据限制。

- 目标候选排序原先在比较器里重复计算威胁与打断判断，间接重复读取报告租约。现按一次候选决策固定排序键，保持打断、威胁、距离、UUID 的优先顺序，玩家拥挤限制仍在排序后按原顺序判定。

## 伤害回执

- 伤害分配层按来源及本次调用消费盾牌回执；成长层单独聚合同一实体的实际生命损失，子伤害归子来源。外层结束时现在先移除已空的线程局部栈，再进入奖励结算。保留已有的 tick 末清理，用于原版或联动伤害调用抛出异常、未触发 RETURN 注入的情况。

- 战斗经验奖励按士兵 UUID、雇主和已应用序号发放。确认死亡并移除实体时清除该士兵未领的奖励，避免永久滞留。普通卸载、跨维度与被图腾救下的实体不会走此清理。世界账本和实体分开落盘的故障恢复仍需验证。

## 远程监控声音

- 原生声音完成广播后，服务端对有效监控会话补发相同声音数据。先过滤服务器、维度和排除玩家，再查询监控实体。目标视点在听觉距离内时才核查原生收件人去重。TaCZ 原生区块跟踪名单仍用于精确去重。

## 士兵装备交换

- 装备交换先申请整组资源，再验证真实物品引用，分离旧引用后才发布新位置。失败回滚只操作已尝试的槽位。尚未写入的槽位不会为回滚先清空再装回，避免重复触发装备回调。仍只恢复空槽中不存在于其他位置的原始引用。

- 背包编辑锁使用每次打开菜单独有的服务端令牌。旧菜单关闭、断线后遗留菜单和实体迁移按该令牌归还锁，避免容器编号复用误认会话。原版菜单清理抛出异常时仍归还对应锁。

## 投掷物提交

- 投掷先锁定真实物品及背包，工厂仅接收副本，原生入场前扣除一件。发布回调异常时，若弹体已加入或已经移除，按已有不可撤回事务规则保留扣除，并向调用方返回成功以完成冷却。未发布的异常仍沿原回滚路径。

## 巡逻编辑

- 路点几何修改先验证，再统一中断旧移动、清除运行游标和发布新版本。补齐编辑后的最小几何约束，删除唯一不同路点后不会留下两个同格的无效巡逻点。停留时间修改使用原有定义更新入口。

## 阵营数据快照

- 阵营关系、专精及装备配置先验证，再在服务器重载应用阶段发布。原阵营快照暴露了可变装备 JSON，调用者可以绕过重载改写默认数据。现构造和读取均隔离可变对象，并在发布装备前先完成阵营快照构造。两个模块仍各有发布点，验证范围是服务器应用线程。

- 单次敌对/同盟查询固定读取一个阵营版本，并复用已取得的定义判断敌对优先级。自然战场配对直接比较同一批候选定义，省去把 ID 转为字符串再解析的往返，也防止换版时抽到无对手的阵营。

- 小队面板的可下令统计与批量执行共同核对名册和当前实体雇主，排除已移除实体。批量执行一次取得名册入口，仍逐成员读取当前所有权。

- 投掷提交后复核调用者。焦燃投掷已在声音前结算，喷溅药水的两个入口改为在同一成功路径内先写冷却再播放音效，避免音效回调跳过正式冷却。

- 导航预算组合复核区分取消预约与取消已执行任务。未消费的预约释放后，同一实体的新任务可使用当 tick 剩余额度；已经领用的批次继续挡住重复领用。其他请求的预约不受影响。

- F8 导航预算快照分别显示已领用与尚未领用的预约，等待数标明为待轮转，涵盖已排入下一轮的请求。诊断从现有计数推导，无额外实体或队列扫描。

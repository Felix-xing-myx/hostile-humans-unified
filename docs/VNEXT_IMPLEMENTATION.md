# 新版本开发接入与验收账本

本文件记录源码责任与实际开发状态；玩法规格以知识库《本轮实施总指引》及其四个详细方案为准。用户已于本轮授权正式开发，静态审查通过后构建同步，部署后暂停等待用户游戏验收。方案中的早期“未授权实施”说明是历史状态，不能据此缩减当前任务。

## 统一入口与职责

| Module | Interface 与不变量 | 接入责任 |
|---|---|---|
| 阵营定义 | FactionDefinitions 的不可变 Revision；重载整表成功后发布，失败保留上一完整版本；未知 ID 不猜阵营 | 主控 |
| 人类身份 | HumanFactions；出生、旧加载与只读查询分开；同群一次选择、旧实体稳定迁移，team 仅派生值 | 主控 |
| 政治声望 | FactionStandingData 存真实值与每日额度；StandingPolicy 为唯一数值规则；不读取客户端配置或旧身份牌 | 主控 |
| 玩家绑带 | IdentityBands.selected；等级优先，同级按专用／通用／背包和稳定槽序；一次选择供关系、宽容和渲染使用 | 主控 |
| 关系与伤害许可 | 统一返回关系原因；有效雇主优先，政治／即时敌意独立；许可不制造视觉确认 | 主控，已接入 |
| 专精与有效属性 | SpecialtyAttributes / EffectiveAttributes；结果存档，查询不抽取；预算内含于乘数，仅输出散布取倒数 | 已交付并整合 |
| 装备与补给 | FactionEquipment 系列集中候选、分档、概率和容量，现有生成入口只做适配；配置保持五文件 | 已交付并整合 |
| 命令与自然状态 | OrderDistances 统一解析有效锚点、日常／追击范围；所有移动消费者读同一结果；小队批处理复用单兵写入口 | 已交付并整合 |
| 界面与网络 | 服务端校验会话／权限／距离，只读快照；客户端不重算权威值；定义修订与实体身份同步 | 主控，已接入 |

不因职责集中而把所有规则塞进 Human.java / HumanRuntime.java：这些文件只调用生命周期与事件入口。可选联动引用留在专用 Adapter。新状态必须有唯一所有者和清理／保存规则，消费者不得自行再存另一份权威状态。

## 集成审查与验证边界

全部四模块的代码已整合；本文件勾选表示实现与静态审查覆盖，不表示游戏验收通过。构建、最终同步与方案归档的完成状态由维护记录独立登记。

- 基线50ed6db，独立提交按模块及审查修复顺序整合，未覆盖main既有WORKSTREAMS修改。
- 用户追加确认：护甲/韧性对含装备总属性应用专精×头目乘数；普通召援用当前有效绑带，缺少拒绝，流浪者不变。
- HumanDamageEvents是实际损血信息唯一入口。GrowthCombat复用同一HealthLossReceipt跟踪血量写入、嵌套同源写入与不同来源子树；压力与政治事件不能回到扣血前预估。死亡政治结算在KILLED移除时确认，保存原动作时间与目击证据，取消死亡不奖励。
- UnifiedConfig/SpecialtyConfig/FactionEquipmentConfig先准备后发布，坏配置重载保留上个完整配置；FactionDefinitions数据包重载先验证全部关系/维度/装备再同步发布。启动无旧配置才保守回退。
- 旧默认枪概率无法证明用户有意覆盖，不将其迁移为统一阶级概率压平阵营差异；与旧默认不同且新字段未设置时首次迁移，写入收据并备份原文件。未知字段及自定义候选池保留。
- 旧equipment_bias含义不能一致映射概率/数量/档位，详细装备策略是唯一抽样权威；aggression当前不新增阵营战斗性格。两项作为后续单独设计，不能声称已支持所有保留字段。
- 26种自然拼图结构均使用SinglePoolElement，原生设置finalizeEntities=true，STRUCTURE固定第10天基线精确覆盖；结构方块与/place template不默认具备该调用，不猜来源。模板导出/放置旋转镜像适配器仍不在本轮。
- 不支持的附魔标签会提示并忽略；不反射未知医疗setHealth。离线可确认驯服主人仍可扣政治声望，无法确认其创造/旁观状态时不发正战功奖励。

实测记录和日志留在维护目录验证日志；已执行的纯策略、JavaExec、缺依赖链接与静态检查不等同于启动专用服务器或进行游戏行为验收。

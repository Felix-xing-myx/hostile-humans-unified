# 本地维护环境的构建同步

维护目录现在使用统一入口，详细步骤、恢复方式和安全检查见：

[发布流程](../../maintenance-tools/发布流程.md)

```powershell
# 在源码仓库的上一级维护目录执行；版本与摘要使用本轮实际值。
python -X utf8 maintenance-tools/release.py run --snapshot --version 3.14.0 --summary "共享界面、据点培养、钱包通行与监控修复"
```

这是当前本机维护环境的辅助工具，公共克隆仍可按AGENTS.md中的显式API路径运行Gradle。入口不代替源码审查，也不扩大构建、实例同步或GitHub推送授权。

固定构建工作树会在源码归属哈希核对后复用缓存；每轮静态与知识库检查只运行一次，Java仍执行完整build/check及lootScreeningTest。日志保存到维护目录，只有阶段摘要与失败原因返回对话。

实例运行时暂停部署，退出后用`deploy --version <本轮版本>`继续，不必重跑相同源码的构建。输入发生变化时会拒绝复用旧的通过结果。


TaCZ原生第一人称检查区分编译API与目标实例依赖。统一辅助脚本从release-settings.json指定实例的[[mods]]声明按modId发现实际TaCZ，再传入-PtaczRuntimeJar；新增接口契约逐一核对这两份JAR，不把编译通过当成实例兼容。公共克隆可显式传目标JAR；未指定时只检查编译API。依赖文件均只读，构建不会替换实例中的TaCZ。


Arcana混合封装会继续读取嵌套`META-INF/mod.jar`中的真实modId声明，按目标实例参数执行共存合同；不依某个版本文件名猜测兼容。新功能方块/物品由实际注册ID驱动原生模型读取，资源图、贴图和双语名称一起核对。独立代理不分别全量构建，公共集成完成后集中执行一次完整build/check。

`namespace_resources_check.py`属于历史命名空间迁移对照，不是当前新增资源清单检查；不得用其`--write`把当前资源恢复成旧迁移快照。当前资源采用原生模型/协议合同和发行输入清单验证。接口或布局重构后，静态回归应继续验证原行为约束，不能继续假定被替换的绘制方法名称或旧协议号。


版本和CHANGELOG已由主控整理时使用`--snapshot`：核对目标版本高于上次发行且与当前源码一致，仍备份、校验、构建和同步，但不暂存、提交或合并已有WIP。源码必须在构建前完成版本与日志；`deploy`继续读取发行状态，无需再次传此选项。传统自动升版模式仍保留用于干净的既有维护流程。

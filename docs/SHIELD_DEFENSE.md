# 举盾防御维护入口

`ShieldDefenseController` 是每个人类共用的举盾策略入口，由 `Human.humanGunner$shieldDefense()` 延迟创建。不新增 Goal、世界扫描任务或静态实体缓存。

## 当前调用关系

- `AdaptiveCombatGoal`：调用 `findIncomingArrow`、`wantsCombat` 判断是否开始防御；调用 `beginCombat`、`tickCombat`、`maintainCombat`、`endCombat` 管理战斗举盾。Goal 继续负责阶段调度、导航和实际反击。
- `BodyguardMovementGoal`：调用 `tickBodyguard`、`endBodyguard` 管理不赋予攻击目标的贴身挡护，Goal 继续负责站位和跟随。
- `RecoverySupplies`：只调用 `requestRecoveryReblock`；请求的有效期、消费条件和存档键由控制模块负责。
- 控制模块：统一保存箭矢抽签、受击/枪击记录、预测检查间隔、战斗/护卫冷却及当前举盾来源；唯一策略执行入口 `raise` 调用 Human 的原生物品使用包装。
- `Human`：保留原生使用物品、移动惩罚、破盾冷却、朝向与客户端同步。普通伤害及 TaCZ 伤害处理仍沿用已有入口。

收盾核验来源以及正在使用的实际 ItemStack；物品使用被攻击、换装或其他应急行为中断后，旧记录不能取消新使用的物品。战斗开始接管护卫举盾时先释放护卫记录；举盾被近战前摇拒绝时不登记虚假的所有权。

## 本次范围与后续策略

本次只统一入口，保留现有概率、持续时间、反击窗口和配置，不声称已经修复近战过早收盾。原有三种冷却规则集中维护，但尚未改为同一数值。

已讨论的箭矢方向：首次来箭进行轨迹预判，受到同一可见射手攻击后结合再次射击准备提前警戒；取消阶级随机概率，挡过一轮后保留反击机会。检测强化、扫描预算和有效格挡建立时间需在后续实现中一起处理，目前未实施。

近战待讨论：现有“满6 tick且处于可反击距离就收盾”和“短暂无压力就收盾”缺少对下一次攻击节奏的判断；受击反应与主动预判应使用同一威胁状态。恢复后的独立请求仅改变一次启动机会，更适合在策略更新时改为恢复结束重新评估威胁，不能把恢复完成直接视为需要举盾。

验证分为源码契约、Java语法解析、编译及游戏行为；前两项不能替代后两项。未收到构建要求前不编译或部署。

只读核对当前Forge映射JAR的LivingEntity.isBlocking字节码：原生有效格挡要求物品使用至少5 tick。当前远程预判在预计2.5 tick内命中才启动，预测窗口最多3 tick，两者不匹配；后续箭矢策略必须把有效格挡建立预算算在提前量内。本次没有改动该规则。

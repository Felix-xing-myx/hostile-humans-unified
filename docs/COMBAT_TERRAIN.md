# 战斗地形决策

本模块处理地面战斗中的路径停滞、危险落差和悬崖受击。它由现有武器与防御 Goal 调用，不注册独立 MOVE Goal，不接管伤害、动画、弹药、换弹、低血量撤退或水中上岸。

## 接口与所有权

- `HumanTerrainSafety.assessPath/assessStep`：只读评估，返回原因及受阻通行方向。规划候选失败不能写入通行记忆。
- `HumanNavigation.moveTo/tick`、实际 `guardTravel`：只有执行被拒绝才报告 `CombatTerrainNavigation.blocked`。每人最多记住12条定向通行，通常60 tick后到期，不封死整个落脚节点。原防摔伤害预算不变。
- `PursuitNavigation`：刷新普通追击、保留仍归属自己且安全的旧路径；部分路径必须检查 `getEndNode()` 实际末端，不能拿 `getTarget()` 请求目的地证明进展。
- `CombatTerrainNavigation.update(human,target,speed,canFire)`：统一决策；`canFire` 由实际武器控制器按视线、射程及弹药可用性提供。防御使用相同武器范围，但不改变原盾牌反击时机。

| 结果 | 调用者职责 |
|---|---|
| NORMAL | 按原逻辑控制移动和攻击 |
| ROUTE | 保留模块路线；继续允许当前武器攻击 |
| PENDING | 等待共享预算或下一批候选；不得新增竞争路线 |
| WAIT | 等待限频重试；不得切回盲目直接追击 |
| FIRE | 停止自身追击路线、保持射界；继续原射击/装填流程 |

PENDING/WAIT允许仍安全且实际前进的旧追击路线继续运行；停滞或失效路线必须停止。只使用 `MovementContinuity.ownsRoute` 停止自己的路径，不清除其他 Goal 的路线。通用导航修复遇到地形模块路线时让出移动，由模块监测实际位移。实际移动遭否决后清除缓存侧移和短步，避免下一 tick重复施加旧输入。

目标死亡、失去攻击许可、换目标/武器/维度、命令切换、撤退、水中、上岸或攀爬会清理模块状态。所有状态只在服务器维护；不会新增存档兼容数据或客户端控制入口。诊断键 `hostile_humans_unified:terrain_obstruction` 和 `combat_terrain_state` 仅用于观察最后原因/决定，不参与行为判定。

## 搜索与战术

1. 两次确认失败、实际位移停滞40 tick，或最终安全否决，进入受阻判断。普通失败每10 tick最多累计一次；等待预算不计失败。
2. 如果当前能射击，优先维持远程回答；不能侧移不等于不能射击。
3. 否则依次使用8、16、24格半径，包含朝向目标的前、侧、后八个方向和两种距离。每列优先当前高度附近，向上最多4格、向下最多12格，保留最多三个有效层。完整路径允许暂时背离敌人。
4. 候选必须已加载、位于世界边界/建造高度内、无危险和流体、有站立碰撞面及身体空间；实际路线必须完整、安全、遵守士兵活动限制。最终移动安全仍逐步检查，不允许靠中间点跨越危险落差。
5. 每次获准最多检查两条候选，复用战斗共享预算，不增加预算池容量。完整路线每10 tick复查，下一节点的指令限制每 tick检查，底层导航持续检查下一段高度安全。相同目标移动四格只刷新样本，不清空活动绕路或失败记忆。
6. 到达绕路中间点后重新尝试目标；若再次失败，扩大下一轮搜索半径。最多记住16个已尝试末端、保留100 tick，避免短时间围绕同一末端反复重走。
7. 普通绕路耗尽且正在受攻击时，尝试8格范围掩护。必须同时遮挡敌人眼睛到士兵眼睛/躯干的射线；单纯更远不算掩护。到达后等待40 tick再尝试追击。搜索全部失败时也等待40 tick，不每 tick穷举。

远程地形近战切换必须满足实际可攻击，或得到能接近到近战距离的完整安全路径。地形近战与普通弓弩近距离托管是不同入口，不能把前者当成所有弓弩的固定等待时间；恢复远程不要求周围有足够侧移空间。普通弓弩临时近战由RangedHybridMeleeGoal继承原MeleeAttackGoal：累计80个实际近战tick后在安全边界尝试找射位，搜索最多40 tick，成功安装路线后才释放旧追击；主动脱离最多80 tick或停滞20 tick，失败回近战并重新累计周期（重试门槛60 tick）。至少六格且有射界才尝试归还武器，已提交攻击继续受CloseDefenseHold保护。正常射击仍由武器Goal执行，地形模块不直接开火或修改攻击冷却。

普通食物/金苹果由OffhandFoodUse独立副手动作推进，不占主手原生用物状态、不新增MOVE/LOOK、不停止追击或地形路线，也不附加进食减速；药水和医疗用品仍按原恢复会话处理。地形安全、正常跳跃与真正追击跳砍继续由原控制器决定，不能用“正在吃东西”推导独立逃跑路线或暂停导航。

驻守不离位；贴身保护绕路各节点保持主人12格追击范围；跟随/巡逻等遵守原命令范围和驻守追击例外。目标允许被远程攻击不意味着允许走出命令范围。

## 验证与限制

已执行的 Python 检查是源码接入契约，不能证明路径在实际地形中成功。Java `CombatTerrainPolicyTest` 覆盖决策边界和编译后调用链，登记至 Gradle check；遵守构建授权，未构建时不能声称已执行。

游戏内验收清单：

- 陡坡旁有坡道/楼梯，先背离目标才能到达的路线，以及左右两个候选只有一条可走。
- 悬崖上下和隔崖对射：可射击保持远程，不可接近不盲切近战；有掩体时尝试遮挡，无路时限频重试。
- 桥下、树冠下、半砖/楼梯边缘、窄路转弯，以及路径途中方块被移除。
- 移动目标、目标死亡/切换、换枪、命令切换、贴身保护主人移动、低血量撤退、水边接战。
- Better Combat前摇/出伤与切武器、TaCZ换弹和射击，以及同时多士兵战斗的服务器耗时。

搜索是有界启发式，不保证任意迷宫或超过预算/范围的道路都能找到。射线遮挡也不代表能抵挡所有模组的穿墙弹、爆炸或范围攻击。这些限制不通过强制移动、传送或放宽防摔来隐藏。


## 雇佣士兵受困救援

服务器生命周期的 `SoldierStuckRecovery` 独立于武器Goal及目标存在与否，补足有仇恨时闲置跟随救援不运行的问题。先让现有导航/绕路尝试工作；持续约10秒无实质位移后，分两次、受共享寻路预算约束，检查返回命令目的地是否不可达。正常可达路线、预算等待和正常站在命令点不作为受困失败。跳跃撞墙不能反复重置时钟。

跟随和护卫回有效主人附近，区域驻守回命令锚点附近，巡逻回最近成功规划的巡逻终点附近（记录随实体保存，缺少时回巡逻中心）；原地驻守不参与。安全位置复用 `SafePositions`，检查身体碰撞、危险地形、世界边界与已加载区块；没有安全落点则等待重试。传送成功后清理旧目标及移动状态，普通选敌短暂停2秒、救援冷却10秒，保持命令和攻击模式；苦力怕救主例外保留。该模块不新增常驻范围扫描或竞争MOVE的Goal，不在撤退、涉水/上岸、熔岩应急等状态接管移动。

源码契约通过不能证明实际坑洞与其它模组地形上的路径判定、Mixin或落点行为；本次新增Java回归待构建，以上游戏场景仍需验收。


## 2026-10-11 当前苦力怕的近战击杀承诺

苦力怕开始引爆时，撤离入口先核对它是否确实是该人类当前的仇恨目标。只有当前手持可近战武器、未使用物品、目标可见且允许攻击，才评估持续攻击。远处另一只苦力怕不借用此例外；贴身保护原有的救主例外继续独立生效，低血撤退和高压防御也不被覆盖。

预计伤害沿用分阶、成长与经验倍率，计入武器附魔、Better Combat当前连击/横扫、目标护甲、抗性、保护附魔及吸收生命。第一击用当前连击倍率，后续以连击中较低伤害估算；不依赖未来暴击、火焰或队友补刀。原生及其它模组额外取消/改写伤害的事件仍可能使实际结果不同，这是一项风险评估而非击杀保证。

预计命中时间包含当前近战冷却、Better Combat未完成前摇、目标受伤冷却与接近时间。未进入攻击距离时只读取现有可达路径，不新建寻路；最多检查12个剩余节点和12 tick接近预算，拒绝涉水、明显落差与不可达终点。已开始的攻击若来不及接近则不算有效命中。后续攻击间隔至少10 tick；最后预计命中必须比该苦力怕实际剩余引信提前超过2 tick。条件不足时维持撤离，满足时不让苦力怕撤离Goal清除当前目标或取消攻击前摇；后续继续复查。

接口：CreeperMeleeCommitment汇总只读预测，CreeperFinishPolicy计算时间预算，AvoidCreeperGoal统一决定是否撤离。MeleeAttackTiming只旁记冷却截止时间，不改变各Goal的攻击节奏。Better Combat复用原有命中范围查询，仅在当前附近苦力怕正在引爆且通过前置条件时使用；不新增常驻扫描Goal。

验证：142项Python静态/API契约检查通过。新增9项Java时间/伤害边界用例尚未编译执行。尚未构建、同步或游戏验证。待验收：短武器可秒杀、两击能/不能赶上引信、Better Combat前摇中引爆、吸收/抗性、目标移开/掉入坑、水边不可达、附近第二只苦力怕、贴身保护救主和低血撤退。


## 2026-10-11 水面战斗移动控制（待构建）

静态审查发现：非跟随的普通战斗仍可选择WaterBoundPathNavigation，而Human移动始终按站立浮在水面执行，水下节点不能正确完成；原近战进入命中范围后可能残留旧追击路径；水中MOVE_TO只保护Better Combat前摇朝向，没有保护盾牌朝向；受阻监测原先把任意水平位移都算作进展，因此绕圈也能反复延迟换路。拾取Goal已有目标/受击禁用，未发现其正常允许战斗中寻物，但其旧局部移动请求在选敌切换时可能残留。

统一入口仍为WaterCombatNavigation → PursuitNavigation → Human.approachCombatTargetInWater，不新增MOVE Goal。普通近战、弓弩临时近战和举盾近战推进复用此入口。普通战斗的导航与跟随一样保持canFloat地面寻路，不用水下节点要求人类下潜；低血撤退、显式上岸路线和射击上岸租约仍由原所有者控制。

当前合法近战目标在水面、8格内、垂直差不超过1.5格且可见时，优先用现有直向水中推进。每次仍检查前方0.75格身体碰撞和命令允许位置；有阻碍时不硬推崖壁，交还预算寻路和原上岸绕行。当真实MeleeCombatRange.canStrike允许命中时停止旧路径、清理侧移、每帧柔化水平惯性，并朝向目标等待/执行原冷却与攻击，避免继续绕过对手。盾牌有效朝向和Better Combat前摇朝向优先于路径朝向；追击速度保留调用方输入并限制异常值。每帧移动请求不跨目标继承，通用导航修复在该帧让出控制。

受阻看是否缩短了至少0.5格水平目标距离；原地绕圈和上下浮动不算进展。如果目标本身移动，则人类朝目标方向前进至少0.5格、侧向位移不超过前进的75%也算正常追击，避免对等速逃离目标误判卡住。仍使用既有停滞时长、全局寻路预算、40 tick搜索间隔和失败岸点避让；不增加持续范围扫描。抵达命中范围后可以提前归还本入口自己的上岸绕路，不覆盖其它上岸所有者。

水中近战追击可见的同在水中目标（12格内）时，远处射手的新命中不直接抢走这个目标；更近的真实威胁、贴身护卫优先级、低血撤退和高压防御仍保留。正式取得目标时清理旧拾取局部请求；水中战斗结束后3秒内暂缓拾取，approachWaterLoot自身也拒绝有目标/逃跑时执行。战斗中的被动附近拾取继续走统一SoldierPickupPolicy。

验证：150项Python静态/API检查通过；新增12项Java纯策略边界用例尚未编译执行。本轮无构建、同步、游戏启动或推送。待游戏验收：双近战在开阔浅水/深水水面接近并命中；有远处射手时不异常折返；盾牌朝向与推进一致；死亡目标/丢失目标附近大量掉落物；高崖/窄水道绕路；跟随/护卫/驻守命令边界；低血撤退与临时近战还弓；多单位战斗开销。

# 战斗地形决策

本模块处理地面战斗中的路径停滞、危险落差和悬崖受击。它由现有武器与防御 Goal 调用，不注册独立 MOVE Goal，不接管伤害、动画、弹药、换弹、低血量撤退或水中上岸。

## 接口与所有权

- `HumanTerrainSafety.assessPath/assessStep`：只读评估，返回原因及受阻通行方向。规划候选失败不能写入通行记忆。
- `HumanNavigation.moveTo/tick`、实际 `guardTravel`：只有执行被拒绝才报告 `CombatTerrainNavigation.blocked`。每人最多记住12条定向通行，通常60 tick后到期，不封死整个落脚节点。原防摔伤害预算不变。
- `PursuitNavigation`：刷新普通追击、保留仍归属自己且安全的旧路径；部分路径必须检查 `getEndNode()` 实际末端，不能拿 `getTarget()` 请求目的地证明进展。
- `CombatTerrainNavigation.update(human,target,speed,canFire)`：统一决策；`canFire` 由实际武器控制器按视线、射程及弹药可用性提供。防御使用相同武器范围，但不改变原盾牌反击时机。

| 结果 | 调用者职责 |
|---|---|
| NORMAL | 按原逻辑控制移动和攻击 |
| ROUTE | 保留模块路线；继续允许当前武器攻击 |
| PENDING | 等待共享预算或下一批候选；不得新增竞争路线 |
| WAIT | 等待限频重试；不得切回盲目直接追击 |
| FIRE | 停止自身追击路线、保持射界；继续原射击/装填流程 |

PENDING/WAIT允许仍安全且实际前进的旧追击路线继续运行；停滞或失效路线必须停止。只使用 `MovementContinuity.ownsRoute` 停止自己的路径，不清除其他 Goal 的路线。通用导航修复遇到地形模块路线时让出移动，由模块监测实际位移。实际移动遭否决后清除缓存侧移和短步，避免下一 tick重复施加旧输入。

目标死亡、失去攻击许可、换目标/武器/维度、命令切换、撤退、水中、上岸或攀爬会清理模块状态。所有状态只在服务器维护；不会新增存档兼容数据或客户端控制入口。诊断键 `hostile_humans_unified:terrain_obstruction` 和 `combat_terrain_state` 仅用于观察最后原因/决定，不参与行为判定。

## 搜索与战术

1. 两次确认失败、实际位移停滞40 tick，或最终安全否决，进入受阻判断。普通失败每10 tick最多累计一次；等待预算不计失败。
2. 如果当前能射击，优先维持远程回答；不能侧移不等于不能射击。
3. 否则依次使用8、16、24格半径，包含朝向目标的前、侧、后八个方向和两种距离。每列优先当前高度附近，向上最多4格、向下最多12格，保留最多三个有效层。完整路径允许暂时背离敌人。
4. 候选必须已加载、位于世界边界/建造高度内、无危险和流体、有站立碰撞面及身体空间；实际路线必须完整、安全、遵守士兵活动限制。最终移动安全仍逐步检查，不允许靠中间点跨越危险落差。
5. 每次获准最多检查两条候选，复用战斗共享预算，不增加预算池容量。完整路线每10 tick复查，下一节点的指令限制每 tick检查，底层导航持续检查下一段高度安全。相同目标移动四格只刷新样本，不清空活动绕路或失败记忆。
6. 到达绕路中间点后重新尝试目标；若再次失败，扩大下一轮搜索半径。最多记住16个已尝试末端、保留100 tick，避免短时间围绕同一末端反复重走。
7. 普通绕路耗尽且正在受攻击时，尝试8格范围掩护。必须同时遮挡敌人眼睛到士兵眼睛/躯干的射线；单纯更远不算掩护。到达后等待40 tick再尝试追击。搜索全部失败时也等待40 tick，不每 tick穷举。

远程地形近战切换必须满足实际可攻击，或得到能接近到近战距离的完整安全路径。保留近身反击持武器时长；恢复远程不再要求周围有足够侧移空间。正常射击仍由武器 Goal 执行，模块不直接开火或修改攻击冷却。

驻守不离位；贴身保护绕路各节点保持主人12格追击范围；跟随/巡逻等遵守原命令范围和驻守追击例外。目标允许被远程攻击不意味着允许走出命令范围。

## 验证与限制

已执行的 Python 检查是源码接入契约，不能证明路径在实际地形中成功。Java `CombatTerrainPolicyTest` 覆盖决策边界和编译后调用链，登记至 Gradle check；遵守构建授权，未构建时不能声称已执行。

游戏内验收清单：

- 陡坡旁有坡道/楼梯，先背离目标才能到达的路线，以及左右两个候选只有一条可走。
- 悬崖上下和隔崖对射：可射击保持远程，不可接近不盲切近战；有掩体时尝试遮挡，无路时限频重试。
- 桥下、树冠下、半砖/楼梯边缘、窄路转弯，以及路径途中方块被移除。
- 移动目标、目标死亡/切换、换枪、命令切换、贴身保护主人移动、低血量撤退、水边接战。
- Better Combat前摇/出伤与切武器、TaCZ换弹和射击，以及同时多士兵战斗的服务器耗时。

搜索是有界启发式，不保证任意迷宫或超过预算/范围的道路都能找到。射线遮挡也不代表能抵挡所有模组的穿墙弹、爆炸或范围攻击。这些限制不通过强制移动、传送或放宽防摔来隐藏。


## 雇佣士兵受困救援

服务器生命周期的 `SoldierStuckRecovery` 独立于武器Goal及目标存在与否，补足有仇恨时闲置跟随救援不运行的问题。先让现有导航/绕路尝试工作；持续约10秒无实质位移后，分两次、受共享寻路预算约束，检查返回命令目的地是否不可达。正常可达路线、预算等待和正常站在命令点不作为受困失败。跳跃撞墙不能反复重置时钟。

跟随和护卫回有效主人附近，区域驻守回命令锚点附近，巡逻回最近成功规划的巡逻终点附近（记录随实体保存，缺少时回巡逻中心）；原地驻守不参与。安全位置复用 `SafePositions`，检查身体碰撞、危险地形、世界边界与已加载区块；没有安全落点则等待重试。传送成功后清理旧目标及移动状态，普通选敌短暂停2秒、救援冷却10秒，保持命令和攻击模式；苦力怕救主例外保留。该模块不新增常驻范围扫描或竞争MOVE的Goal，不在撤退、涉水/上岸、熔岩应急等状态接管移动。

源码契约通过不能证明实际坑洞与其它模组地形上的路径判定、Mixin或落点行为；本次新增Java回归待构建，以上游戏场景仍需验收。

# 玩家巡逻路线与控制物品

源码归属：`soldier` 的 `PatrolRouteEditor`（服务器草稿）、`PatrolRoutes`（持久路线写入）、`PatrolRoutePolicy`（纯拓扑/权限/几何）、`NaturalRoute`（原有执行器）；`client/ui` 的 `PatrolWaitScreen` 与 `PatrolEditorClient` 只负责展示和输入。

## 操作与权限

- 指挥棒 `hostile_humans_unified:patrol_command_baton`：木棍、铁锭、线各一件无序合成。右键驻守人类开始草稿；右键方块按实际碰撞表面记录脚部高度，检查站立净空；蹲右键撤销最近一点；主手持棒时左键清空草稿并结束编辑，不删除已录入路线。再次右键同一人类提交。
- 生存仅可编辑正式雇佣且属于自己的驻守士兵。创造可编辑任意驻守人类，包括他人已雇佣的士兵。选择/提交仍检查存活、同维度与8格交互距离，提交复核权限和路线修订号。切换目标另起草稿，不会把A的路线误写给B。
- 创造控制器 `hostile_humans_unified:creative_soldier_controller` 无配方，仅创造可用；仅操作无主、无临时雇主的人类。右键打开状态与巡逻面板（自由状态也可打开），在面板选择自由/原地驻守/巡逻，调整追击和8～96格范围，查看暂存路线与运行状态，修改路点顺序/删除和停留。打开不会更改状态，自由状态的路线只读；编辑至少保留2点，点位与等待整体交换，改变路线后从首点重新执行。自由状态暂存自然设置、原点与进度，恢复后不丢路线；显式作者clear仍清除设置。
- 正式士兵面板在驻守时有“巡逻路点与停留”入口。专用面板逐点调整0～60秒，步长1秒；64格交互会话、60秒闲置租约、所有权/创造资格、UUID与实体ID、修订号和字段边界均由服务器校验。

## 草稿生命周期

草稿只存在服务器按玩家保存的有界内存结构，不进入物品NBT、实体NBT或存档。双手任一手持指挥棒均保留草稿；两手均未持有后连续2400游戏tick（20TPS为120秒）释放，重新拿回则重置离手计时。下线、死亡换体、跨维度、服务器停止和目标确认死亡/移除会清理。目标仅卸载时不强制加载，允许继续草拟；录入时必须重新找到存活目标并复核权限。

选点上限沿`orders.route_max_points`，默认64，配置范围2～256；用于闭环的末次起点标记不占实际路点数。相邻点直线距离最多96格，不能把它理解成导航路程上限；绕路搜索仍受现有地形安全、加载与算路配额约束。

## 拓扑与执行

- 开放路线沿输入顺序到另一端，再沿同一路点序列返回，持续往返。
- 只有最后一点明确回到起点、且中间没有重复路口、回折或同层交叉的简单闭环才用loop。末尾重复起点在保存时去掉，避免重复停留。
- “6”形、闭环带进出口、重复路口或自身交叉都按ping_pong处理，保留输入序列。不同楼层的跨越不直接当作同一平面路口。
- 继续使用原有`NaturalRoute`、`RouteProgressPolicy`、`BasicNavigationBudget`、路径跟随与落差/碰撞安全，不新建Goal或单独扩大搜索配额。玩家路线的失败点是必经点：失败后按现有退避重试，不默默跳点。
- 玩家路线沿用`orders.route_timeout`，但按“持续缺少实际路径进展”计时；节点推进且实体确实移动会重置它，长路线不会仅因正常步行超过10秒而被取消。原模板路线仍保留原先的单点总执行时限与失败跳点规则。

## 坐标、中心与移动权限

路线使用作者数据中冻结的`route_origin`和相对路点，`player_route=true`标明玩家绘制路线。录入后中心先落在起点，每到达一个点才更新真实的玩家岗位锚点或自然原点，等待、追击和战后返岗都读这个中心；路线坐标不会跟着中心整体平移。重新设岗等显式命令仍按各自原有语义处理。

当前一段路线安装期间和拥有已安装路径时，允许沿该段的有界走廊跟随，防止正常巡逻被旧岗位圆截断；走廊宽度取驻守活动半径，仍检查地形和危险。该许可只用于本执行器的路径；战斗、调查、拾取仍使用当前路点的原有范围，不能借巡逻走廊扩大追击。接管、背包编辑、固定点测试、撤退和返岗不会取得这个走廊许可。

完整路线保存到现有`order_garrison`或`natural_state`，进度继续使用各自原有runtime键。模式/半径变化停止旧路径，但玩家路线保留顺序进度。`NaturalState.authorOnly`排除玩家路线的世界固定原点及相关字段，避免把世界坐标错误导出为可旋转结构模板；旧本地作者路线继续按原规则导出。

## 默认与修改入口

| 项目 | 默认/限制 | 入口 |
|---|---|---|
| 离手缓存 | 2400tick，20TPS为2分钟 | `PatrolRoutePolicy.AWAY_TIMEOUT` |
| 路点数 | 64，配置2～256 | `orders.route_max_points` |
| 相邻直线距离 | 96格 | `PatrolRoutePolicy.MAX_LEG` |
| 单点停留 | 默认0，0～1200tick | `orders.route_wait_default`、逐点面板 |
| 到达水平/垂直容差 | 1.5 / 0.75格，并检查遮挡 | `orders.route_reach_distance`、`route_vertical_tolerance` |
| 无进展时限 | 200个实际执行tick | `orders.route_timeout` |
| 失败退避 | 100tick | `orders.route_failure_backoff_ticks` |
| UI距离/租约 | 64格 / 1200tick | `PatrolToolNetwork` |

维护时同时检查源数据、保存与恢复、事件输入、执行权限、客户端协议和知识库。不要把路线草稿放进客户端权威状态，也不要通过永久NoAI或传送来完成巡逻。

## 草稿线框与状态协议

指挥棒选点后服务器单播已确认草稿，最多257个上方方块框；仅握棒且同维度时绘制128格内的点，起点绿色、最新点黄色、其余青色。撤销、取消、提交、超时及目标移除同步清理。巡逻草稿与导航诊断共用客户端DebugWorldLines的缓冲和RenderType，渲染不分配逐帧原生缓冲，不扫描世界或重新寻路。PatrolToolNetwork协议升级2；创造会话与普通士兵停留会话分别授权，只有前者可修改自然状态与路线结构，服务器每20tick刷新、1200tick闲置租约，继续核对实体ID/UUID/距离/归属/修订。
